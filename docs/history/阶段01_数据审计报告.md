## 4. SFT 数据包装与划分

- 训练 1,506 个目标回合，涉及 225 段对话、44 个关联分组。
- 开发 201 个目标回合；分组为 17 个。
- 格式：prompt 是历史消息；completion 是一个客服目标回合；tools 是固定环境的 15 个函数 schema；metadata 记录来源、长度、分组和转换次数。
- 只监督 completion，历史 assistant 也只作上下文；独立 thinking/reasoning 字段不进入非思考模式消息。
- 原始系统指令要求 valid JSON only，与普通客服回复及 Qwen 工具协议不一致，已统一为公共客服指令、固定官方政策和原生工具 schema。
- 原始政策比选定官方政策弱两处：操作前确认措辞、每回合最多一个工具；差异保存在 outputs/policy_diff.txt。最终各阶段统一官方规则。
- 原始历史中存在并行查询。只对匹配已有返回的并行只读查询改成顺序调用，并删除该查询批次伴随的口头说明，不新增顾客回复或工具结果。每条样本记录 repacked_read_batches。
- 多写历史、目标回合同时发言/调用或多工具、非法参数、显式思考内容等不自动修复，保留排除原因。
- 采用完整关联分组选择，故数量不恰好等于 1,500/200；不为了凑数拆分关联组。

## 5. 长度与训练边界

结构规范化后可渲染 8,350 个 Retail SFT 回合，均使用真实 Qwen tokenizer、官方政策、完整工具 schema 和非思考模板。其余回合因格式或内容问题被排除，不能把长度统计理解为全部 11,395 条的分布。

| 指标 | 完整序列 token 数 |
| --- | ---: |
| 最短 | 4,830 |
| 中位数 | 6,656 |
| P95 | 9,747 |
| 最长 | 14,209 |
| 超过 8,192 | 1,549 |

保留到处理后 SFT 文件的样本均不超过 8,192，不截断政策、目标答案或工具返回。所有可渲染样本的“上下文 token 是完整样本精确前缀”检查通过；这不代替阶段五的跨轮采样前缀和 loss mask 验证。
训练数据共 9,155,318 个上下文加目标 token，其中实际监督目标 159,438 个；两者不能混淆。GPU 前向仍需处理上下文，不能仅按目标 token 估算训练费用。

**重要限制：换货目标长对话较多，8K 筛选后只有 9 条可用且不与 RL 留出集关联的完整换货目标。已优先分配训练 8 条、开发 1 条。** 原始换货示范中的 84 条因长度被排除。这个覆盖偏少，SFT 阶段需要检查换货开发能力；若不足，再依据显存与预算讨论更长上下文或适当数据包装，不能直接宣称换货冷启动充分。

## 7. 留出集隔离

- 分组键：对话、scenario、顾客邮箱/用户 ID、订单 ID，以及相同或高度相似的长诉求文本。
- 高度相似文本先检查词集合 Jaccard>=0.75，再检查 SequenceMatcher>=0.9；不足 12 个词的近似匹配不使用该规则，相同且不少于 8 词的描述直接关联。
- 支付方式示例 ID、产品和规格不是顾客身份；不会因此把所有样本错误连成一组。
- SFT 与 RL 训练组可以关联；训练与各开发/最终测试之间，以及不同留出集之间不允许身份、订单和关联分组交叉。
- RL 留出任务关联的可用 SFT 样本已排除。每个目标回合和 RL 任务的分组、划分、排除原因记录在 splits.json。
- 独立检查发现跨划分实体与关联分组重叠为 0。
- 检查不是语义层面的无泄漏证明；未公开模板来源和未达到阈值的同义改写仍可能相似。30 条测试任务也包含关联组，应按小样本探索报告，而不是宣称 30 个完全独立业务模板。
