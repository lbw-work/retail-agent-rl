## 已固定的起点

- 模型：Qwen/Qwen3-4B，非思考模式，英文客服；从已经评测的 SFT LoRA 继续，底座冻结，不重新初始化 LoRA。
- 数据：`data/versions/retail_rl_v3/processed/rl_train.jsonl`，94 条 TRAIN 任务，49 个来源组；冻结清单 `data/versions/retail_rl_v3/manifests/review.json`。dev 使用同版本 16 条；test 22 条留出，不参与训练或检查点选择。历史 29 条池全部包含在新 train 中；原六个划分、快照与 SFT 未修改。
- 框架：Torch 2.8.0、Transformers 4.57.6、TRL 0.26.2、PEFT 0.18.0、Accelerate 1.12.0。CUDA 依赖仍须在服务器重新验收。
- 初始配方：每组 4 条；温度 0.8，无 top-k/top-p 裁剪；单轨迹微批 1，梯度累积 4；LoRA r=16/alpha=32/dropout=0；学习率 5e-6；beta=0；奖励 A；先验证一次更新。
- 奖励版本：`business_subset_v2_us_country`，只在评分副本中将地址国家 USA/US/United States 统一为 USA，其余整个数据库字段仍精确比较。A=`gate × training_business_reward`；官方严格 `business_reward` 同时保留。该规则已获确认，32 条旧轨迹已另存新旧分数，29 条任务的 145 个奖励场景通过；不直接把这次重评分当作训练提升。旧 v1 诊断不与新版本混算或跨版本恢复采样。
- 16,384 token 是完整轨迹安全上限，24 个动作/每动作 512 token 是交互上限，均不是 24G 显存可训练的保证。
- 顾客目标规则：新训练侧顾客应显式采用 `scenario_locked_v1`，同一配置用于本轮训练侧验证。不要静默改变已完成开发集评测的顾客条件；若后续 dev 改用新规则，须重新进行原模型/SFT/GRPO 同条件对照并单独报告。

## 一次更新的数据流

1. 从可信 TRAIN 池选择任务 ID。ID 用于索引环境，不作为客服提示。客服只接收政策、工具 schema 和公开对话，不能看到隐藏目标、金标准变体 ID 或参考动作。
2. DeepSeek 依据原始 `user_scenario` 生成一次顾客开场。将相同开场交给组内四次尝试，每次重新建立数据库和顾客实例。
3. CUDA 当前策略逐回合生成客服实际 token，同时保留采样概率。工具执行后把真实返回追加到上下文，顾客 API 只看公开对话，不看工具结果。
4. 正常结束或已定义的模型动作/长度限制到达后，由环境重放和奖励检查给整条轨迹判分；API/环境故障中止整组，不伪装为业务零分。
5. 将同组四条奖励交给原生 TRL 计算优势。只优化实际客服 token；顾客、工具反馈保留注意力上下文，但损失掩码为 0。
6. 更新前在完整真实上下文中重算概率，检查与实际采样概率的一致性；然后检查损失、梯度，执行一次更新，保存新的 LoRA 检查点。

05C 的 MLX 轨迹只用于判断任务和奖励是否有学习信号。05D 必须在 CUDA 重新采样，不能直接把旧 MLX 轨迹送入 on-policy 更新。

## 验收顺序与停止条件

| 顺序 | 操作 | 通过条件 | 未通过时 |
| --- | --- | --- | --- |
| 1 | 核对费用、模型/任务哈希和 CUDA 依赖 | 输入与已验收成果一致；明确租卡实价及本轮限额 | 不启动 GPU 付费采样 |
| 2 | 在训练后端做受控采样和概率重算 | 实际 token 原样保留；概率最大差 ≤0.05；组内提示一致 | 修复采样/训练策略差异，不放宽阈值掩盖问题 |
| 3 | 验证完整历史与损失掩码 | 顾客/工具损失梯度为 0；客服有梯度；旧历史未重编码或截断 | 修复输入与掩码，不进入更新 |
| 4 | 可信任务的一组真实交互 | 4 条完整尝试、独立状态；有真实成功/失败差异；API 记录关联可复核 | 同分组如实保留；故障不补零分；只继续可信 TRAIN 任务 |
| 5 | 一次真实参数更新与重载 | 损失/梯度有限且非零；LoRA 参数确实变化；检查点可重载；记录显存/耗时/API 费用 | 保存停止证据，不能宣称训练完成或效果提升 |

若 24G 显存不足，先检查概率重算及损失的实际显存峰值，再提出针对性的实现调整。不能静默截断历史、降低完整轨迹上限后把截断失败当业务失败，也不能跳过概率一致性检查。

正式开启 GPU 前仍须确认实际已花的服务器金额和新的 GPU 额度。用户此前只确认服务器费用不超过 35 元，项目 GPU 上限也是 35 元；不能把总预算剩余自动视为新的 GPU 授权。总预算 50 元与 5 元收尾预留保持不变。
