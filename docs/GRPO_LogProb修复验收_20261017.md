# GRPO LogProb 修复验收（2026-10-17）

训练链路已跑通。保留原 0.05 概率门槛，完成真实 smoke、最终版本两步验证、完整 checkpoint 保存及独立 CUDA 重载。完整 94 步和业务提升评测尚未执行。

## 原因与最小修复

相同参数下，逐 token 采样和整段训练的数值执行路径不一致。BF16 的形状相关舍入沿网络放大；改成 FP16 后仍有新采样超差。提高精度后，bitsandbytes 的单向量 GEMV 与整段 NF4 矩阵路径也会产生差异。另确认 TRL 0.26.2 初始化会隐式降低 QLoRA 适配器精度。

最终 GRPO 入口统一 FP32 计算，关闭 autocast/TF32，共用原 bitsandbytes `MatMul4Bit.apply` 矩阵路径及 Efficient SDPA，显式展开 GQA。原 NF4 权重、BF16 量化输入和 SFT FP32 适配器原值保留。奖励、学习率、组大小、温度、掩码及 0.05 门槛未调整，没有新增依赖。

正式训练允许合法同分组的有限零梯度；smoke 仍要求非零梯度。少于五步的短程验证每步保存，长程仍每五步保存。
